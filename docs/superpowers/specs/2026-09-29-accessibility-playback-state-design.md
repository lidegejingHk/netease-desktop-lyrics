# 网易云 macOS 播放状态修复：设计

日期：2026-09-29

## 已验证问题与证据

当前 3.1.12 客户端暂停后，CoreAudio `IsRunningOutput` 仍可能为真；原始位置停住，估算位置继续前进。LevelDB 的 `lastPlaying` 记录约 6 秒后过期，CLI 改报 `NoSong`。不能把音频进程活动当作播放状态，也不能延长旧磁盘记录的新鲜期。

本机 macOS 26.6.2 已通过只读 AX 探测：在网易云未置前、菜单未展开的情况下，`AXApplication → AXMenuBar → 标题为“控制”的 AXMenuBarItem → AXMenu → AXMenuItem` 可读取准确的“暂停”（正在播放）或“播放”（已暂停/待播放）标题；实际播放和暂停各验证一次。`AXManualAccessibility`、`AXEnhancedUserInterface` 写属性在本机返回错误，无须依赖它们。只访问菜单属性，不执行 `AXPress`、不展开菜单、不改变客户端数据。读取需执行探针的应用/终端已有 macOS 辅助功能授权，缺少授权时只报告诊断，不自动弹授权框或修改系统设置。

## 边界和接口

- `accessibility`：独立 macOS AX FFI，输入网易云主进程 PID，返回 `Playing`、`PausedOrIdle`、`PermissionDenied` 或 `Unavailable`。只识别“控制”菜单下一级菜单中的**精确**动作标题（中英文），角色也要符合；冲突/菜单缺失/查询失败均为不可用，不猜测。限制遍历规模与 AX 响应时间；不输出其他菜单/私人数据。
- `PlaybackTracker`：注入 PID、AX 状态、LevelDB 原始观测和单调时间；只在状态可靠且 ID/进度存在时生成快照。播放中缺原始观测返回 `NoSong`，不沿用旧歌。暂停期间读不到新记录时，仅保留**同一 CLI 进程、同一网易云主 PID**中已验证的最后一首与冻结位置，输出 `held_paused=true`，原始进度注明为旧观测。暂停时拿到新的有效记录则替换它；进程退出、更换 PID、权限/格式/状态错误时立即清除。冷启动已暂停且无近期记录时返回 `NoSong`，不扫描 `.ldb` 历史。
- `Timeline`：只有 AX 明确 `Playing` 才用单调时钟推进。首次暂停不额外前进，保持上一位置；暂停期间新原始进度按原模型校准，恢复播放后根据新观测重建；绝不将估算时间描述为播放器实测时间。
- CLI：`playing=` 仅来源于 AX；`held_paused=` 标记冻结保持，方便区分当前原始观测与保留值。未授权输出 `AccessibilityPermissionDenied`，菜单不可用输出 `MissingField("is_playing")`。保留 `audio` 模块作为历史诊断代码，但不用于生产状态判断。README 写清辅助功能授权方法、版本限制、冷启动暂停的限制和输出定义。

## 验收

1. 合成测试覆盖菜单标题分类、冲突/缺失/权限、暂停超过 6 秒保持、恢复后旧记录不得继续播放、错误/进程重启清除、暂停拖动时新观测校正；原有 41 项测试继续通过，fmt/clippy 干净。
2. 本机只读观察播放、暂停至少 8 秒、恢复、上一首/下一首和进度拖动（如 UI 允许），比对菜单信号与 CLI，日志中匿名化歌曲标识，不提交真实记录。
3. 若 AX 授权或菜单在目标设备不可用，CLI 显示准确缺项而不是 `playing=true`；不退回 CoreAudio 猜测。歌词请求、LRC 引擎、AppKit 窗口和安装包是**另一个阶段**，不在本次代码范围内。

已知限制：菜单“播放”本身不能区分「已暂停」与「没有可播放曲目」；同一进程暂停期间若外部改变曲目而客户端没有写出新 `lastPlaying`，保留快照无法及时察觉。`held_paused=true` 明确表示这个不确定性，不称其为新鲜观测。网易云或 macOS 升级后要重新现场验收。
