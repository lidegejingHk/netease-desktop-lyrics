# 浮层歌词可见性、整首歌进度与歌名设计

## 已验证根因

用户现场截图中外框与按钮可见，歌词与声浪均不可见。WindowServer 读到歌词窗和声浪窗仍在预期矩形，单独截取两窗可见非透明内容；背景窗在同层窗口列表里位于这两窗前面，且背景不透明度当前为 100%。拖动使 `OverlayFrame.follow` 与歌词、声浪等窗口在相同 `.floating` 层反复 `setFrame`，相对叠放顺序不稳定。不是歌词数据中断或窗口丢失。不要用“重启引擎”“取消黑底”“禁用拖动”掩盖这个 bug。

## 修复

把唯一背景窗固定到**低于歌词与声浪、高于普通窗口**的层级；两内容窗仍为 `.floating`，可点图标仍高一层。移动时仍以歌词窗为位置来源，所有窗口保持现有屏幕边界与点击穿透。用 WindowServer 窗口顺序断言和合成截图覆盖多次拖动、锁定、长歌词及声浪均不被背景遮住。

## 声浪与时间

底栏**高亮进度覆盖整首歌**，不再按当前句起止时间重新从零走。Rust 本地已解出 `resourceDuration` 并持有 `RawPlayback.duration_ms`；在逐句及开头事件传 `position_ms` 与 `duration_ms`，Swift 计算 `min(position/duration, 1)`，`duration_ms == nil/0` 时不画进度线、不把整段误判完成，但仍按真实播放状态显示动态声浪。时间暂停时冻结、跳转与切歌使用新估算位置；无歌曲时静态基线。动效是**整首歌期间持续的视觉声浪，不是从系统音频采样的实时振幅**，不增加麦克风或系统录音权限。`--stdin` 仅用于合成预览，不控制真实播放器。

## 歌名与排版

左上与右上工具同行：不增加独立卡片，截断单行的歌名限制宽度且可作为空白背景拖动，不让长标题覆盖工具。当前本地播放记录只有 `resourceId`、`current`、`resourceDuration` 等字段，**没有歌名**；不能从歌曲 ID 猜。以验证过的数字歌曲 ID 向网易云同域的歌曲详情接口单独请求、严格限制体积/超时，校验返回歌曲 ID 和非空标题，仅发经现有验证的 ID，不上传本机播放记录或歌词。标题请求不能拖慢歌词请求；晚到或切歌后的过期结果不能显示，离线/失败时隐藏歌名，下一次有效歌曲可再尝试。缓存仅当前进程内，退出清空。

主歌词／翻译或下一句分别保留独立最多两行、超长缩字/省略，**两段间垂直空隙收紧**，同时保持无交叠、居中排版，并与下方播放行间至少 4pt。暂不动整体外框和控制行尺寸。

## 验收

先使 AppKit 顺序、长句间距、Rust 整首歌进度/标题竞态测试红灯，再分别修复并通过；Rust 测试、Swift 严格 typecheck 和签名检查通过。独立 bundle ID 用持续合成流截短句/长句/等待状态；正式 App 仅本地备份替换、打开验收，不推送。辅助功能若因重签失效由用户手动授权。
