# 歌词框内嵌工具条设计

日期：2026-09-30。分支：`feat/embedded-overlay-controls`；仅本地提交。用户用截图明确指出工具条应位于黑色歌词框右上角的红色区域，已确认保留独立窗口、只调整布局与外观。仓库没有 `origin`；新分支从本地 `main` 创建，并快进接入已验收的歌词功能提交。

## 目标

- 工具条（拖动、锁定、样式、收起）在歌词窗口**内部右上角**，不是窗口上方；默认展开，收起后的小按钮仍贴在内部右上角。
- 保留独立透明 `NSPanel`：歌词锁定时 `ignoresMouseEvents=true`，按钮仍能点击。工具条窗口层级高于歌词窗口，歌词拖动、切换屏幕、显示/隐藏时持续跟随。
- 工具条不再有突兀的独立深色胶囊、边框与窗口阴影；图标颜色随用户选择的歌词文字颜色变化，以便在彩色背景上辨认。
- 当前句的普通长度仍水平居中。仅在其绘制内容（包含文字背底）与工具条真实框发生重叠时，将当前句安排在空间更充裕的一侧并限制宽度；副句和进度条原位置不变。收起后重新计算，避免继续为展开宽度让位。

## 布局与边界

`ToolbarPlacement.origin` 在全局 AppKit 坐标中以歌词窗口 `maxX/maxY` 为基准向内缩进 10/6 pt。仍选与歌词相交面积最大的显示器，在该显示器与歌词窗口的可见交集足够容纳工具条时夹紧到交集；交集过窄时至少夹紧到屏幕可见范围。展开与收起均以**右边缘**为锚点。`main.swift` 负责把工具条在歌词窗口中的实时局部矩形传给 `LyricsView`，不依赖屏幕坐标猜测。

`LyricsView` 先按原宽度摆放文字；若当前行的实际宽度（包括背景片左右内边距）与工具条矩形相交，则选择工具条左侧或右侧较宽的可用区域，在该区域内居中/截断。背景片按最终文字标签中心定位、不得越过标签宽度。空白/加载/错误状态沿用同一策略。保持现有歌词、菜单、Rust 引擎与样式持久化不变。

## 验收

- 几何测试覆盖常规窗口、顶部/右侧屏幕边缘、多显示器、无显示器回退、收起后右侧锚定；AppKit 测试覆盖窗口层级、背景透明、按钮可点/锁定点击穿透、普通/长句以及文字背底不压工具条、收起后恢复居中。
- 运行 Swift 与 Rust 测试、Swift macOS 13 严格编译、格式及 Clippy；使用不同 bundle id 的本地预览包核对视觉/交互，避免在开发中反复重签正式 App。
- 最后退出正式 App，保留现有包备份，**只重建正式包一次**并启动。ad-hoc 签名变化可能需要用户在系统设置重新授权；不自动修改 macOS 安全设置，不保存或回复真实歌词/歌曲 ID。
