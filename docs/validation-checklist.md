# 网易云音乐 3.1.12 播放状态现场验收

日期：2026-09-29。设备：Apple Silicon / macOS 26.6.2。本项目只读，不自动操作网易云客户端；播放内容、账号信息和原始日志不要写进 Git。

命令：

```bash
cargo run -- --samples 120 --interval-ms 500
```

逐项在网易云客户端**手动**操作，对照输出 `track`、`raw_ms`、`estimated_ms`、`playing`、`held_paused`，记录可观察到的切换延迟。无需提交真实歌曲标识；可将不同歌曲记为 A、B。

| 操作 | 合格标准 | 本次结果 / 观察延迟 |
| --- | --- | --- |
| 客户端未启动 | `NotRunning`；不沿用上次歌曲 | 待人工验证 |
| 客户端运行但尚未播放 | 不把上次歌误认为当前播放；如有历史快照则标记限制 | 本次用户确认：截图前半段 `NoSong` 时尚未播放，输出符合预期；重新启动场景未测 |
| 开始播放 | `track` 对应实际歌曲，原始进度随播放刷新 | 终端截图证实：从 `NoSong` 切到非空 ID，`raw_ms` 从 164000 递进至 171000，`playing=true`；未核对客户端曲名与实际开始播放时刻，延迟待测 |
| 切歌、上一首、下一首 | ID 与实际歌曲对应，估算进度重置；记录切换延迟 | 待人工验证 |
| 播放 → 暂停 → 恢复 → 暂停 | `playing` 正确切换；暂停时估算进度冻结 | **旧版 CoreAudio 未通过**：用户按此顺序操作；两次 `raw_ms` 停在约 56 秒、64 秒时仍显示 `playing=true`，`estimated_ms` 继续前进，随后出现 `NoSong`；恢复后才重新输出进度。操作时间未逐项标记，无法量化切换延迟 |
| 播放中向前、向后拖动 | 原始进度可观测；向后跳转经第二个递进样本确认 | 待人工验证 |
| 暂停时拖动 | 原始位置变化；估算位置随新样本校正 | 待人工验证 |
| 退出客户端 | `NotRunning`，旧快照不再输出 | 待人工验证 |
| 缺目录、空目录、坏记录、缺字段 | `MissingDirectory`、`NoSong`、`FormatChanged`、`MissingField` 分开报告 | 合成输入单元测试覆盖；实机不修改客户端数据 |
| 权限不足 | 输出 `PermissionDenied`，不提权、不改系统权限 | 临时目录权限单元测试覆盖；未改变网易云目录权限 |

## 已有验证

- 自动化：2026-09-29，`cargo test` **41 passed**（源解码、CRC32C 校验的 LevelDB 完整/半写/分片记录、日志轮转与旧记录过期、进程发现、CoreAudio 未知结果合并、时间模型、CLI 参数、错误路径复位、空目录与权限分类）。
- 实机只读采样：初版在客户端 3.1.12 播放中连续 4 次获得非空歌曲标识，`raw_ms` 递进、`playing=true`。审查修复后，新版探针在未播放时输出 `NoSong`，播放后获得歌曲标识与递进的进度；切歌、暂停、拖动仍未验证。
- 用户终端截图与后续确认：最初的 `NoSong` 发生在**尚未播放**时，开始播放后首次输出歌曲 ID，随后约 0.5 秒间隔得到递进的 `raw_ms`，`estimated_ms` 随播放更新；**命令启动到首个观测约 9 秒不是识别延迟**，实际识别延迟未测。截图含歌曲 ID，本报告不记录该值；尚无歌名对照、切歌/跳转实测。
- 第二次用户回放（播放→暂停→恢复→暂停）：约 `t+9.7s` 到 `t+15.4s`，原始进度约 56 秒不变，估算进度约 56.3→61.9 秒、`playing=true`；随后连续 `NoSong`。恢复后原始进度约 57→64 秒；约 `t+34.0s` 到 `t+39.6s`，原始进度约 64 秒不变，估算约 65.3→70.9 秒、`playing=true`，随后再次连续 `NoSong`。此处 `t+` 是命令启动后的时间；用户未逐项标注按钮时刻，不能精确归因每行，但暂停验收不符合要求。未记录歌曲 ID。
- 辅助功能复验：网易云 3.1.12 主窗口 `AXChildren=0`，但未展开的「控制」菜单可用 `AXMenuBar` / `AXChildren` 在网易云非前台时**只读**获取动作标题。2026-09-29 实机点击播放/暂停后，背景探针分别读得「暂停」/「播放」；不需要对 App 设置 `AXManualAccessibility`（在此机器上返回不支持）。本项目 AX 代码未点击任何控件。
- 对日志格式的适配仅针对当前安装版本；App 升级后需重跑这张表。使用本机活动日志进行只读结构核验：49 条完整 LevelDB 记录的校验值与规格匹配，未保存/提交内容。

## 2026-09-29 新 AX 状态源复验

- 自动测试：`cargo test` **51 passed**；`cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings` 通过。真实 track ID 全部只在本机终端临时显示，分析记录用 A/B 代替。
- 播放：`playing=true`，原始位置在多个样本间从约 239 秒递进到约 269 秒；菜单动作为「暂停」。
- 暂停：一个轮询间隔左右出现 `playing=false`，估算位置停在约 270.7 秒；同一客户端随后写入一条新标识 B、`raw_ms=0` 的完整记录，CLI 据新记录切换 B 并冻结 0 ms，`held_paused=true` 持续超过 50 秒没有假推进；新记录为何出现（自动切歌/队列）尚未证实。
- 冷启动已暂停：若无新日志记录，CLI 输出 `NoSong` 而不是上次歌曲。恢复播放后等到新有效记录，再输出 `playing=true` 和递进进度；未使用旧缓存伪装成及时恢复。
- 切歌/上一首/下一首、播放中向前向后拖动、暂停时拖动、退出/重启客户端仍待新版本的现场测试。尚不能声称整体验收全部通过，**不把未知行为写成成功**。

**当前结论：播放/暂停核心误判已修复，已在本机验证长暂停冻结；第一阶段仍有切歌/拖动/退出场景待测。** CoreAudio 路线仍不可靠，生产路径已改用辅助功能菜单。需要完成上表后再宣布全部达标。
